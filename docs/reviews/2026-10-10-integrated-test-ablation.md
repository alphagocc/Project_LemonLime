# 集成测试消融记录

日期：2026-10-10。基础提交：`02dc356`。实验环境：Windows x64、MSVC、Qt 6.12.0、Debug 构建。

## 实验方法

先运行原 `test1`，确认正常版本通过。随后每次临时修改一个生产实现，编译测试并保存 Qt Test XML 中各函数及数据行的结果。每项实验结束后按原始字节恢复源文件，最后重新编译并运行正常版本。

故障集合包含 15 项，覆盖 CDF 字段、编译器配置恢复、工具启动、评测完成标志和判定结果。对精简后的测试使用同一集合；再对每个故障移除其检出测试组，实际运行其余测试组，核对检出能力的变化。编译失败、进程启动失败和测试跳过均作为实验错误单独处理。

本次结果用于比较这组故障的检出能力。Linux 与 macOS 的运行验证仍由相应环境完成。

## 保留与精简依据

CDF 读取和保存分别具有独立检出作用，合并为一个往返测试并保留比赛名称、任务名称、参赛者名称等固定期望。这样同时检查原对象与重建对象，避免仅比较两个同样缺少字段的对象。测试增加了每道题测试点数量的校验。

工具位置检查原本独自发现 Python 启动失败，因此需要先补齐实际评测断言。完整评测现在检查四个选手与题目的组合，包含 Python 正确答案、缺少源码、C++ 各测试点判定、编译状态和完成标志，随后删除独立的工具位置检查。

删除 `default-configuration` 数据行：在本次矩阵中，它仅检出过时编译器条目，其他保留行具有同样作用；完整评测同时使用默认编译器配置。保留缺少条目、失效名称、空字符串、自定义配置和禁用配置五行。其中空字符串有独立检出的故障，失效名称保留既有配置兼容回归场景。

完整评测只执行一次，通过结果表检查所有组合。错误输出与空输出、内存消耗与异常终止继续保留。异常终止样例使用显式 `std::raise(SIGSEGV)`，保留 Unix watcher 的信号终止检查并消除数组越界及缺少返回值的未定义行为。

测试准备仅解析一次 CDF，仅在评测时复制样例；局部对象按作用域管理，目录恢复守卫先于临时目录清理执行。CMake 集中查找 Qt Test，删除重复链接和构建阶段的数据副本。

## 验证材料

本机原始材料保存在 `build/integrated-test-ablation-20261010/`。`before` 是原测试，`after` 是第一次三组测试对照，`final` 和 `final-resume` 保存最终五行配置版本的故障矩阵与实际逐组消融输出。`run_ablation.py` 包含各项修改及恢复逻辑。
