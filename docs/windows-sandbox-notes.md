# Windows 沙箱备忘录

本文件保留 2026-09-15 至 2026-09-28 的设计实验与验证摘要。各项数字属于记录日期对应实现的本机结果，不能视为当前提交的验证结果。现行配置、行为和维护约定统一见 [Windows 沙箱](windows-sandbox.md)。

## 设计决定

2026-09-15 确定使用 AppContainer 与 DACL 隔离提交程序，提供 C、C++、Java、Python 策略和额外只读目录。编译器与检查器隔离另行设计。准备预算最终采用可配置值，默认 15 秒；磁盘或系统调用的响应时间仍受操作系统影响。

2026-09-16 起，临时授权与 Python 发现结果按活动评测会话管理，使用独立命名 capability SID 和内存记录，在最后一个使用者退出时撤销授权。此前文件缓存、文件锁与整份工作目录 DACL 快照属于历史实现。按当前 DACL 删除本次 SID 允许项，可以保留其他活动任务后来追加的授权；临时目录由原有 `QTemporaryDir` 生命周期删除。

2026-09-16 统一限制为一个活动进程，保留主进程用户态时间、峰值工作集和原有超时、内存限制、取消处理。需要子进程的 Python 启动器及 Windows venv 因此须使用基础 Python 等单进程入口。此前 venv 成功执行的记录对应允许 Python 创建子进程的版本。

## 2026-09-15 消融实验

实验以 686 行的 `windowssandbox.cpp` 为基准，基准沙箱测试为 32 项通过。各版本使用本机 Qt 6.9.3、MSVC、C、C++、uv Python 启动器、venv 和 Scoop Java。原记录将实验副本及输出保存于 `build/sandbox-ablation`。

| 实验 | 当时结果 | 后续处理 |
| --- | --- | --- |
| 用 `GetEffectiveRightsFromAclW` 替换 ACL 扫描 | 8 项针对性测试通过；Python 首次准备由 1621 增至 9723 毫秒，Java 由 131 增至 1204 毫秒 | 保留按 ACE 顺序扫描 |
| 合并 Python 探测与提交程序的进程属性配置 | 14 项针对性测试通过 | 可信探测最终使用普通 `QProcess` |
| 合并运行环境与私有文件权限处理 | 32 项通过；Python 首次准备 1502 毫秒，复用 34 毫秒 | 保留共用的权限处理 |
| 使用 QSettings 缓存 | 32 项通过；Python 首次准备 1660 毫秒，复用 33 毫秒 | 后续改为会话内存记录 |
| 使用 QFileInfo 目录连接接口 | 10 项针对性测试通过 | 后续交由 Windows 文件接口跟随连接 |
| 使用 `QDir::canonicalPath()` 并让 Windows 跟随运行目录连接 | 10 项针对性测试通过，包含 Scoop Java、目录连接及目录重叠 | 采用该实现 |

一次目录解析替换实验得到 31 项通过、1 项失败。失败原因是实验删除连接解析后仍保留主动拒绝重解析点的检查，使 Scoop Java 在权限准备时被项目代码拒绝。该结果仅说明实验版本的行为，无法证明 Qt 或 Scoop 缺少目录连接支持，也无法证明手工解析必须保留。原记录中的核查文件为 `qt-path-results.txt` 与 `qt-path-process.log`。

该阶段先将格式化后的源文件从 686 行缩至 566 行，随后增加编译器切换复用、工具更新失效、并发准备、目录连接及目录重叠测试，完整 CTest 的两个测试集通过，沙箱测试为 41 项通过、零跳过。后续会话清理版本曾为 734 行，再缩至 670 行；两个测试集和 43 项沙箱测试通过。源文件行数仅记录当时规模。

## 历史性能样例

128 个运行文件首次准备约 70 至 120 毫秒，复用约 20 至 40 毫秒；本机 Java 首次配置 579 项权限约 529 毫秒，复用约 30 至 40 毫秒。Python 完整目录检查约 1 至 3 秒，命中准备记录时通常约 30 至 50 毫秒，测试中也出现过 173 毫秒。复用测试确认运行库 ACL 更新次数为零。

以上样例用于说明当时的首次准备与复用差异，耗时取决于安装规模、磁盘和系统状态。编译器与检查器隔离、任意第三方运行环境适配仍属于后续设计事项。
